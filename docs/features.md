# Features

What's actually implemented, not what's planned — see [ROADMAP.md](ROADMAP.md) for the feature plan and tracking issues. Update this file whenever a feature is added or its status changes.

| Feature | Status | Details |
| --- | --- | --- |
| Self-hosted server configuration | Has UI | A public server URL and an optional private (LAN) URL, with automatic switching to the private one on trusted Wi-Fi networks. Entered via `ServerSetupScreen`. See [networking-auth.md](networking-auth.md) and [app-shell.md](app-shell.md). |
| Account authentication | Has UI | Login, TOTP MFA, logout, and expiry-aware session persistence, against Trek's single-JWT session model. `LoginScreen`/`MfaScreen` wire this into the app shell; the router redirects between server setup, login, and the trip list automatically as auth state changes. See [networking-auth.md](networking-auth.md) and [app-shell.md](app-shell.md). |
| App shell (navigation, state management, design system) | Foundational, one feature screen | Riverpod + go_router + a Material 3 design system (including Trek's place category colors), a global snackbar messenger, and a reusable UI kit (empty/loading/skeleton states, cards, list rows). Trip list and trip dashboard (with Days/Places/Budget/Packing/Todos tabs) exist as placeholders — no trip data model yet; transit + airport search is the first real feature screen. See [app-shell.md](app-shell.md). |
| Transit & airport search | Has UI | The `/transit` screen (reached from the trip list's app-bar transit icon) does public-transit stop search, route planning between two stops, and airport lookup against `GET /api/transit/geocode`, `GET /api/transit/plan`, and `GET /api/airports/search`. Reads go through `TransitRepository`: the last results for a query paint from a local `shared_preferences` cache first, and a failed refresh falls back to that cache with an offline notice instead of blanking or throwing. Also adds the app's first authenticated (bearer-token) `ApiClient`. No departure-time picker, no transit-mode filters, and no creating an itinerary entry from a result (needs the Days feature, [#4](https://github.com/ryanmac8/trek-native-app/issues/4)). See [transit.md](transit.md). |
| App icon, splash screen & startup animation | Done | The real Trek T-mark (from the web client's source SVG) as the app icon and native launch image, plus an animated in-app splash screen styled after Trek's web login screen. See [app-shell.md](app-shell.md#app-icon-splash-image-and-startup-animation). |
