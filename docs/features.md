# Features

What's actually implemented, not what's planned — see [ROADMAP.md](ROADMAP.md) for the feature plan and tracking issues. Update this file whenever a feature is added or its status changes.

| Feature | Status | Details |
| --- | --- | --- |
| Self-hosted server configuration | Has UI | A public server URL and an optional private (LAN) URL, with automatic switching to the private one on trusted Wi-Fi networks. Entered via `ServerSetupScreen`. See [networking-auth.md](networking-auth.md) and [app-shell.md](app-shell.md). |
| Account authentication | Has UI | Login, TOTP MFA, logout, and expiry-aware session persistence, against Trek's single-JWT session model. `LoginScreen`/`MfaScreen` wire this into the app shell; the router redirects between server setup, login, and the trip list automatically as auth state changes. A rejected token (401) no longer signs the user out — see "Sync resilience" below. See [networking-auth.md](networking-auth.md) and [app-shell.md](app-shell.md). |
| Biometric app lock | Done | Face ID / Touch ID / Android biometric unlock gates re-entry to an already-authenticated session, once per cold start. Falls back to full password re-login if biometrics fail or aren't available. See [biometric-lock.md](biometric-lock.md). |
| Sync resilience (auth failures don't block the app) | Done | An authenticated `ApiClient` now exists; a 401 flags `AuthService.needsReconnect` instead of clearing the session, and a persistent (non-blocking) banner with a "Reconnect" action shows over the trip screens instead of forcing a logout. See [networking-auth.md](networking-auth.md#authenticated-requests--sync-resilience). |
| App shell (navigation, state management, design system) | Foundational | Riverpod + go_router + a Material 3 design system (including Trek's place category colors), a global snackbar messenger, and a reusable UI kit (empty/loading/skeleton states, cards, list rows). Trip dashboard (with Days/Places/Budget/Packing/Todos tabs) still placeholders — no per-trip data model yet. See [app-shell.md](app-shell.md). |
| App icon, splash screen & startup animation | Done | The real Trek T-mark (from the web client's source SVG) as the app icon and native launch image, plus an animated in-app splash screen styled after Trek's web login screen. See [app-shell.md](app-shell.md#app-icon-splash-image-and-startup-animation). |
| Trips — list (read-only) | Data layer + UI, read-only | `TripListScreen` fetches and renders real trips via `GET /api/trips`. No create/edit/delete, no local caching/offline writes yet (full trip management is [#3](https://github.com/ryanmac8/trek-native-app/issues/3); persistence is [#21](https://github.com/ryanmac8/trek-native-app/issues/21)). See [app-shell.md](app-shell.md). |
