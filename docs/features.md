# Features

What's actually implemented, not what's planned — see [ROADMAP.md](ROADMAP.md) for the feature plan and tracking issues. Update this file whenever a feature is added or its status changes.

| Feature | Status | Details |
| --- | --- | --- |
| Self-hosted server configuration | Has UI | A public server URL and an optional private (LAN) URL, with automatic switching to the private one on trusted Wi-Fi networks. Entered via `ServerSetupScreen`. See [networking-auth.md](networking-auth.md) and [app-shell.md](app-shell.md). |
| Account authentication | Has UI | Login, TOTP MFA, logout, and expiry-aware session persistence, against Trek's single-JWT session model. `LoginScreen`/`MfaScreen` wire this into the app shell; the router redirects between server setup, login, and the trip list automatically as auth state changes. See [networking-auth.md](networking-auth.md) and [app-shell.md](app-shell.md). |
| App shell (navigation, state management, design system) | Foundational, one feature screen | Riverpod + go_router + a Material 3 design system (including Trek's place category colors), a global snackbar messenger, and a reusable UI kit (empty/loading/skeleton states, cards, list rows). Trip list and the trip dashboard (Days/Places/Budget/Packing/Todos/Bookings tabs) exist as placeholders except Bookings. See [app-shell.md](app-shell.md). |
| App icon, splash screen & startup animation | Done | The real Trek T-mark (from the web client's source SVG) as the app icon and native launch image, plus an animated in-app splash screen styled after Trek's web login screen. See [app-shell.md](app-shell.md#app-icon-splash-image-and-startup-animation). |
| Reservations — list | Data layer + UI | The trip dashboard's Bookings tab lists a trip's reservations from a trip-scoped local cache first (instant, works offline), then refreshes from `GET /api/trips/:tripId/reservations` in the background; if that fetch fails and nothing is cached, it shows an explicit offline/error state with a retry. Each row shows a per-`type` icon, the booking title, a detail line (start time → location → linked place → itinerary day), and a confirmation-number icon; a cancelled booking is marked in its detail line. Reachable via the trip dashboard route (`/trips/:tripId`) directly — the trip list has no trips to tap into yet. Read-only: no create/edit/delete, no day/place picker, no multi-leg transport detail, no travelers. See [reservations.md](reservations.md). |
