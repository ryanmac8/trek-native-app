# Features

What's actually implemented, not what's planned — see [ROADMAP.md](ROADMAP.md) for the feature plan and tracking issues. Update this file whenever a feature is added or its status changes.

| Feature | Status | Details |
| --- | --- | --- |
| Self-hosted server configuration | Has UI | A public server URL and an optional private (LAN) URL, with automatic switching to the private one on trusted Wi-Fi networks. Entered via `ServerSetupScreen`. See [networking-auth.md](networking-auth.md) and [app-shell.md](app-shell.md). |
| Account authentication | Has UI | Login, TOTP MFA, logout, and expiry-aware session persistence, against Trek's single-JWT session model. `LoginScreen`/`MfaScreen` wire this into the app shell; the router redirects between server setup, login, and the trip list automatically as auth state changes. See [networking-auth.md](networking-auth.md) and [app-shell.md](app-shell.md). |
| App shell (navigation, state management, design system) | Foundational | Riverpod + go_router + a Material 3 design system (including Trek's place category colors), a global snackbar messenger, and a reusable UI kit (empty/loading/skeleton states, cards, list rows). Trip list and trip dashboard (with Days/Places/Budget/Packing/Todos tabs) exist; Places now reads real data, the rest are still placeholders — no trip data model yet, so the trip list/dashboard aren't reachable from real trip data. See [app-shell.md](app-shell.md). |
| App icon, splash screen & startup animation | Done | The real Trek T-mark (from the web client's source SVG) as the app icon and native launch image, plus an animated in-app splash screen styled after Trek's web login screen. See [app-shell.md](app-shell.md#app-icon-splash-image-and-startup-animation). |
| Places — place pool | Data layer + UI | The trip dashboard's Places tab reads a trip's places from a trip-scoped local cache first (instant, works offline), then refreshes from `GET /api/trips/:tripId/places` in the background, over the app's first authenticated `ApiClient`. Each row shows the place's name, price/currency + notes, and a category badge colored from its real assigned category. Places can be created (add button), edited, and deleted (tap a row) — name, description, address, category, price/currency, notes — offline-first: changes apply locally at once, queue in a per-trip outbox, and replay in order, with Trek's `X-Base-Updated-At` optimistic concurrency; a 409 marks the row as conflicted and the user picks keep-mine or use-theirs. The form's category picker offers the server's categories (`GET /api/categories`), cached locally so it works offline; a category picked offline shows on the row at once. Not yet: custom-category create/edit/delete (admin-only on the server), tags, coordinates/map, place detail view, bulk actions, search, importers, or filtering to just the unassigned pool; and since trips (#3) aren't built on `main` yet, the dashboard itself isn't reachable from real trip data, only via its route directly. See [places.md](places.md). |
